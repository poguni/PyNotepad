1. 개요

항목내용
앱 이름PyNotepad (창 제목: 제목 없음 - Windows 메모장)
한 줄 소개Windows 11 메모장(notepad.exe 10.0.26100)을 바이너리 분석으로 재현하고, 테마·줄 번호·마크다운 미리 보기를 더한 Python/Tk 텍스트 편집기
대상 사용자한글 문서를 많이 쓰는 Windows 사용자. 가볍고 익숙한 메모장 조작감에 보기 편한 화면을 원하는 사람
형태Windows 데스크톱 앱. 소스 실행(pythonw notepad.pyw) 또는 단독 실행 파일(dist\PyNotepad.exe, 18.2 MB)
규모앱 코드 pynotepad/ 10개 모듈, 테스트 7개 파일, 합계 약 2,950줄. 테스트 63개
개발 기간재현판 기본 구현은 이 보고서의 세션 이전에 완료. 이 보고서가 다루는 개선 작업은 2026-10-17 ~ 2026-10-18

2. 목표 및 배경

  • 원본 동작을 근거 있게 재현: 겉모습만 비슷하게 만든 것이 아니다. REA 6.5.0과 Ghidra 12.1.4로 notepad.exe와 한국어 리소스(notepad.exe.mui)를 분석했고, 메뉴 구성, 단축키, 인코딩 판별 순서, .LOG 동작, 상태 표시줄 문구를 원본에서 확인한 대로 옮겼다(docs/ANALYSIS.md).
  • 한글 사용 환경 개선: Tk 기본 동작에서 불편했던 점을 직접 보완했다. 작은 IME 창에 따로 보이던 조합 중인 글자, 맑은 고딕 고정 메뉴가 그 대상이다.
  • 원본과 다른, 보기 편한 디자인: 이번 작업의 주제다. 기능은 그대로 두고 "너무 화려하지도, 너무 심플하지도 않은" 화면과 직관적인 새 아이콘을 만들었다. 시인성 좋은 UI 글꼴도 적용했다.
  • 쉬운 배포: 설치 없이 실행되는 exe 파일 하나로 만들었다.

3. 주요 기능

원본 메모장과 같은 기능

  • 파일: 새로 만들기, 새 창, 열기, 저장, 다른 이름으로 저장(인코딩 선택), 인쇄, 끝내기, 저장 안 한 변경 확인
  • 편집: 실행 취소, 잘라내기·복사·붙여넣기·삭제, Google로 검색(Ctrl+E), 찾기·다음 찾기·이전 찾기, 바꾸기·모두 바꾸기, 줄 이동, 모두 선택, 시간/날짜(F5)
  • 서식/보기: 자동 줄 바꿈, 글꼴, 확대/축소(10~500%, Ctrl+휠), 상태 표시줄
  • 인코딩: BOM → IsTextUnicode → UTF-8 검사 → ANSI 순서로 자동 판별. 저장할 때 인코딩과 줄 끝(CRLF/LF/CR)을 유지
  • 원본의 특수 동작: .LOG 파일에 시간 자동 기록, NUL 문자를 공백으로 치환, 1 GiB 이상 파일 거부, 최근 문서 등록
  • 단축키: 원본 가속기 테이블 그대로. Ctrl 조합은 가상 키 코드로 처리해서 한글 입력 상태나 Caps Lock에서도 동작

추가 기능

  • 줄 번호: 현재 줄 번호를 굵게 표시. 자동 줄 바꿈된 줄은 첫 줄에만 번호를 붙임
  • 한글 조합 인라인 표시: 조합 중인 글자를 커서 위치에 본문 글꼴로 바로 그림(Win32 창 프로시저 서브클래싱)
  • 마크다운 미리 보기: .md 파일을 렌더링된 화면으로 열고, 원본 보기와 전환. 외부 패키지 없이 직접 구현
  • 테마 2종 — 종이 / 슬레이트 (이번 작업): 메뉴 막대 오른쪽 끝의 테마: 종이 ▾ 드롭다운으로 바꿈. 색, UI 글꼴, 창 아이콘, 문서 이름 표시 방식, 제목 표시줄 색이 함께 바뀜
  • 문서 줄 (이번 작업): 메뉴 막대 아래에 문서 이름을 테마 글꼴로 표시. 저장 안 된 상태는 종이 테마에서 수정됨 칩, 슬레이트 테마에서 탭 옆 점(●)으로 표시
  • 현재 줄 강조 (이번 작업), 상태 표시줄 한글화(줄 3, 열 30) (이번 작업)

테마 구조

  • 테마 하나는 themes.THEMES의 사전 하나다. 색 토큰 약 30개, 글꼴 이름 3개, 아이콘 파일, 문서 줄 방식(header / tab)을 담는다.
  • NotepadApp.apply_theme()는 이 사전만 읽어서 메뉴 막대, 메뉴, 문서 줄, 편집 영역, 줄 번호, 상태 표시줄, 아이콘, 제목 표시줄을 다시 칠한다.
  • UI 글꼴은 tkfont.Font 객체를 다시 설정하는 방식이라, 위젯을 다시 만들지 않아도 창 전체에 바로 반영된다.

단계시점내용

1. 코드 분석10-17폴더 구조와 모든 모듈을 읽고 기본 기능을 정리, 테스트 59개 통과 확인

5. 디자인 문서10-18design/DESIGN.md(색 토큰·글꼴·아이콘·구현 제약), 오프라인 시안 HTML, 아이콘 SVG 저장
6. 테마 구현10-18글꼴 동봉, 아이콘 생성, themes.py, 메뉴 막대 테마 드롭다운, 문서 줄, 현재 줄 강조, 상태 표시줄 한글화. 테스트 63개

8. exe 빌드10-18글꼴 축소(17 → 12 MB), "새 창" exe 대응, PyInstaller 단독 exe 18.2 MB, 실제 실행 검증

6. 주요 의사결정과 이유

결정이유
시안 A·B를 둘 다 테마로 구현사용자 요청. 테마를 데이터(색 토큰 사전)로 분리해 두면 추가 비용이 작음
기본 테마·기본 아이콘은 종이사용자 결정
테마 선택은 메뉴 막대 오른쪽 끝 드롭다운사용자 요청. 처음 설계(DESIGN.md)의 "보기 > 테마"에서 바꿈. 같은 기능을 두 군데 두지 않음
상태 표시줄 **줄 3, 열 30**사용자 결정. 원본 MUI 문구(Ln %d, Col %d)와 달라지는 점을 resources.py 주석에 남김
제목 표시줄은 직접 그리지 않고 색만 변경하고, 문서 이름은 문서 줄에 표시제목 표시줄 글꼴은 Windows가 정함. 직접 그리면 창 이동·크기 조절·스냅을 모두 다시 만들어야 해서 불안정
글꼴은 앱 안에만 등록 (AddFontResourceExW(FR_PRIVATE))사용자 PC에 설치하지 않고도 사용 가능, 시스템 글꼴 목록을 더럽히지 않음
Noto Sans KR은 정적 OTF를 동봉시스템에 있는 가변 글꼴(VF)은 Tk에서 Medium 굵기를 고를 수 없음
상태 표시줄을 ttk → tk 위젯으로ttk(vista 테마)는 바탕색·구분선 색을 지정할 수 없음
ttk 테마(clam)로 바꾸지 않고 기본 스크롤바 유지clam으로 바꾸면 스크롤바는 칠할 수 있지만 대화 상자 모양까지 바뀜
미리 보기 버튼을 tk.Button → **tk.Label**Windows tk.Button의 안쪽 여백 때문에 메뉴 막대가 17 px 커져 화면이 흔들림
글꼴 축소에서 힌팅 유지빼도 2.3 MB만 줄고, 작은 글자가 흐려질 위험이 있음
exe는 onefile사용자 요청(설치 없는 파일 하나). 대가로 시작할 때 1~2초 압축 해제 시간이 듦
웹 배포는 보류Tkinter 앱은 브라우저에서 실행 불가. HTML/JS로 새로 만들어야 함(12장 참고)

7. 문제 해결 기록

문제원인해결
드라이버가 메뉴를 연 채로 멈춤Tk 메뉴는 Windows에서 모달 루프를 돌고, Tk는 메인 스레드에서만 호출 가능. 보조 스레드에서 winfo_*를 부르면 RuntimeError스크린샷 영역을 메뉴를 열기 전에 계산하고, 보조 스레드에서 촬영 후 메뉴를 닫음
메뉴 닫기용 Esc가 다른 창으로 감keybd_event는 현재 맨 앞 창에 키를 보냄열린 메뉴 창(클래스 #32768)을 찾아 PostMessage로 Esc를 직접 보냄
편집 메뉴 스크린샷 아래가 잘림촬영 영역을 창 크기로만 잡음메뉴의 winfo_reqheight()만큼 영역을 늘림
F3 찾기가 실패select 명령이 커서를 옮기지 않아 끝에서부터 검색함드라이버의 select가 커서도 함께 옮기도록 수정
선택한 글자가 공백으로 바뀐 1회성 현상재현 안 됨. 드라이버가 창을 맨 앞에 띄우는 동안 다른 곳에서 친 키가 들어간 것으로 추정스킬 문서에 "실행 중 키보드 입력 금지"를 적음
제목 표시줄 색이 흰색으로 남음(초기 2회)따로 실험하면 DWM 호출은 성공(HRESULT 0). 이후 8회 반복에서는 재현 안 됨근거 없는 보완 코드는 넣지 않고 한계로 기록(11장). 창이 뜰 때(<Map>) 다시 칠하는 처리는 유지
메뉴 막대 높이가 문서 종류에 따라 바뀜tk.Button의 기본 안쪽 여백Label로 교체해서 52 px(종이)/56 px(슬레이트)로 고정
--specpath build로 빌드하면 글꼴을 찾지 못함PyInstaller가 상대 경로를 spec 폴더 기준으로 해석--add-data에 절대 경로 사용
exe에서 "새 창"을 누르면 -m 파일을 만들겠냐고 물음exe에서는 sys.executable이 exe 자체라 -m pynotepad가 파일 인자로 처리됨sys.frozen이면 exe를 인자 없이 실행
글꼴 축소 효과가 예상보다 작음IBM Plex Sans KR에는 원래 한자가 거의 없음Noto만 크게 줄었고(4.6 → 2.0 MB) 전체는 17 → 12 MB. 크기 추정이 틀렸음을 사용자에게 알림
Playwright가 file:// 접근을 막음보안 설정로컬 HTTP 서버로 시안 HTML을 확인한 뒤 종료

8. 보안/성능 고려사항

  • 링크 열기 제한: 마크다운 미리 보기의 링크는 http/https/mailto만 연다.
  • 설정 파일 분리: 진짜 메모장의 레지스트리 설정을 건드리지 않도록 별도 JSON 파일을 쓴다. 검증 드라이버와 exe 검사도 임시 설정 경로(--out, APPDATA 변경)로 실행했다.
  • 외부 패키지 없음: 앱 실행에는 표준 라이브러리만 쓴다(Pillow·fontTools·PyInstaller는 개발용).
  • 성능: 줄 번호와 상태 표시줄은 idle 시점에 한 번만 다시 그린다. 1 GiB 이상 파일은 거부한다.
  • exe 시작 시간: onefile 방식이라 창이 뜨기까지 1.2~2.2초 걸린다(측정값).
  • 서명 없음: 서명하지 않은 exe라 다른 PC에서 SmartScreen이나 백신이 경고할 수 있다.

10. 배포

  • 현재 방식: dist\PyNotepad.exe 파일 하나(18.2 MB)를 전달하면 설치 없이 실행된다. 빌드 명령은 README의 "실행 파일(.exe) 만들기"에 있다.
  • 소스 실행: pythonw notepad.pyw [파일] 또는 python -m pynotepad [파일] (Python 3.10+).
  • 배포 URL: 없음. git 저장소가 아니며 아직 GitHub에 올리지 않았다.

11. 알려진 한계

  • 제목 표시줄: 글꼴은 바꿀 수 없고 색만 바뀐다(Windows 11 전용). 초기 실행 2회에서 색이 적용되지 않은 적이 있으나 원인을 찾지 못했다.
  • 드롭다운 메뉴: Windows가 직접 그려서 둥근 모서리·그림자는 시스템 기본을 따른다. 마우스 오버 강조색이 테마색으로 나오는지 확인하지 못했다.
  • 스크롤바: 테마 색이 없는 Windows 기본 모양이다.
  • 설정 저장 시점: 끝내기(cmd_exit)에서만 저장한다. 비정상 종료하면 그 세션에서 바꾼 테마·설정이 사라진다.
  • 원본과 다른 점: 페이지 설정 없음(인쇄는 셸 print 동작), GB18030 인코딩 미지원, 저장 인코딩은 별도 창에서 선택.
  • exe: 시작이 1~2초 걸리고, 서명이 없다. 글꼴이 exe 크기의 절반 이상을 차지한다.
  • 플랫폼: Win32 API에 의존해서 사실상 Windows 전용이다.

12. 향후 개선 아이디어 / 업데이트 계획

다음에 하면 좋을 것

  1. 설정 즉시 저장: 테마를 바꾸는 순간 settings.json에 저장하면 비정상 종료해도 유지된다.
  2. exe 크기 줄이기: 종이 테마의 SemiBold 글꼴을 Medium으로 바꾸면 약 2 MB가 줄어든다. 문서 이름이 조금 덜 굵어지는 것과 비교해서 결정한다.
  3. exe 검증 자동화: 이번에 쓴 "임시 APPDATA로 exe 실행 → 창 촬영" 스크립트를 run-notepad 스킬에 넣어, 빌드할 때마다 같은 확인을 할 수 있게 한다.
  4. 제목 표시줄 색 문제 추적: 다시 나타나면 그때의 조건(포커스, 모니터, 테마 전환 순서)을 기록해서 원인을 찾는다.

여유가 있으면

  1. 웹 버전(GitHub Pages): HTML/JS로 새로 만든다. Chrome·Edge는 File System Access API로 로컬 txt/md 파일을 직접 열고 덮어쓰기 저장할 수 있다. 두 테마 시안 HTML, 아이콘, 찾기·마크다운 로직을 재사용할 수 있다.
  2. 코드 서명: 다른 사람에게 배포한다면 SmartScreen 경고를 줄이기 위해 필요하다.
  3. 테마 확장: 어두운 편집 영역 테마(다크 모드), 시안 C(포커스)를 세 번째 테마로 추가하기. THEMES에 사전을 더하는 구조라 비용이 작다.
  4. 스크롤바 테마 색: 대화 상자에 영향을 주지 않도록 스크롤바 스타일만 따로 정의하는 방법을 검토한다.

아이디어 수준

  1. 원본에 있던 페이지 설정(머리글/바닥글 &f, &p)과 GDI 직접 인쇄
  2. GB18030 인코딩 지원(원본 내부 ID 6)
  3. 최근 파일 목록 메뉴, 여러 문서 탭(슬레이트 테마의 탭 디자인을 실제 탭으로 확장)
